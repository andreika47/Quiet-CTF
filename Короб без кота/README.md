# Короб без кота
**CyberCTF 2026**

Дана наивная реализация `VaultKDF` на 12 кубитах: 10 кубитов данных (`0..9`, младший бит первый) и две анцилла (`10`, `11`), которые в конце обязаны вернуться в `|0⟩`. Нужно собрать схему только из `X`, `CX`, `T`, `T†`, которая делает то же самое, но укладывается в бюджет: 12 кубитов, не больше 4 гейтов `T`/`T†`, глубина не больше 48, не больше 64 операций. Наивная схема оценивается в 21 кубит, T-count 741 и глубину 364.

Напомним обозначения. `|0⟩` — это просто состояние бита 0, `|1⟩` — состояние бита 1. Базисное состояние — набор из 12 таких битов, всего их `2^12 = 4096`. Гейт `X` переворачивает бит. `CX(a, b)` переворачивает целевой кубит `b`, если контрольный кубит `a` равен 1, то есть делает `b ^= a`. `CCX(a, b, c)` — вентили Тоффоли: целевой кубит `c` переворачивается, если оба контрольных кубита `a` и `b` равны 1. `T` ничего не делает с `|0⟩`, а `|1⟩` домножает на `ω = exp(iπ/4)`; `T†` домножает на `ω⁻¹`. Так как `ω^8 = 1`, фазу удобно считать целым показателем по модулю 8: `T` прибавляет `+1`, `T†` прибавляет `−1`.

Сервер проверяет эквивалентность без симулятора. Он перебирает все 4096 базисных входов и для каждого гонит биты через схему как через обычную программу, параллельно накапливая показатель фазы. Для эталона то же самое посчитано заранее. Биты на выходе должны совпасть побитово, включая анцилла, а разность `фаза посылки − фаза эталона` по модулю 8 должна быть одинаковой для всех входов — тогда это глобальная фаза, и схема принимается. Если разность хоть на одном входе другая, ответ `candidate is not equivalent to VaultKDF`.

Наивная программа целиком лежит в `challenge/circuit.py`:

```python
def naive_program():
    operations = [
        GateOp("ccx", (0, 1, 10)),
        GateOp("ccx", (2, 3, 11)),
        GateOp("cx", (4, 5)),
        GateOp("ccx", (2, 3, 11)),
        GateOp("ccx", (0, 1, 10)),

        GateOp("add", value=173),
        GateOp("add", value=911),
        GateOp("sub", value=337),
        GateOp("add", value=641),
        GateOp("sub", value=876),

        GateOp("ccx", (0, 1, 10)),
        GateOp("cx", (4, 7)),
        GateOp("ccx", (0, 1, 10)),
        GateOp("ccx", (2, 3, 11)),
        GateOp("cx", (5, 8)),
        GateOp("ccx", (2, 3, 11)),
        GateOp("cx", (0, 3)),
        GateOp("cx", (3, 6)),
        GateOp("cx", (1, 8)),
        GateOp("x", (2,)),
    ]
    operations.extend(_noisy_phase_oracle())
    return tuple(operations)

def _noisy_phase_oracle():
    terms = [
        ((0, 1, 4), (1, 1, -1)),
        ((2, 5), (1, 1, 1, 1, 1, 1, 1, 1)),
        ((3, 6, 9), (-1, -1, 1)),
        ((1, 7), (1, 1, -1)),
        ((0, 8, 9), (-1, -1, 1)),
    ]
    operations = []
    for mask, coefficients in terms:
        for coefficient in coefficients:
            operations.extend(parity_gadget(mask, coefficient))
    return operations

def parity_gadget(mask, coefficient):
    bits = tuple(mask)
    pivot, controls = bits[-1], bits[:-1]
    operations = [GateOp("cx", (control, pivot)) for control in controls]
    phase_gate = "t" if coefficient > 0 else "tdg"
    operations.extend(GateOp(phase_gate, (pivot,)) for _ in range(abs(coefficient)))
    operations.extend(GateOp("cx", (control, pivot)) for control in reversed(controls))
    return operations
```

Цены из `resources.py`: `X` и `CX` бесплатны, `T` и `T†` стоят 1, `CCX` стоит 7 (столько гейтов `T` уходит на то, чтобы собрать вентили Тоффоли из разрешённого набора), `ADD` и `SUB` стоят `7 · (2·10 − 1) = 133` каждый и требуют 9 дополнительных кубитов под переносы. Отсюда и наивные цифры: `8 · 7 + 5 · 133 + 20 = 741` гейтов `T`, где `20 = 3 + 8 + 3 + 3 + 3` — число фазовых гаджетов. Видно, что в схеме три дорогих слоя, и убрать нужно каждый: даже если избавиться от вентилей Тоффоли и арифметики, 20 фаз в бюджет из 4 не влезут.

**Вентили Тоффоли.** Все восемь `CCX` стоят парами: `CCX(0,1,10) · CCX(2,3,11) · CX(4,5) · CCX(2,3,11) · CCX(0,1,10)` и ещё две такие же конструкции вокруг `CX(4,7)` и `CX(5,8)`. `CCX` обратен сам себе, а зажатый между парой `CX` действует на другие кубиты (`{4,5}` не пересекается ни с `{0,1,10}`, ни с `{2,3,11}`), поэтому `CX` можно вынести наружу, а две одинаковые `CCX` сокращаются. Это обычная схема compute/uncompute, только здесь посчитанное в анцилла значение никто не читает — это приманки. От трёх конструкций остаются `CX(4,5)`, `CX(4,7)` и `CX(5,8)`. Анцилла `10` и `11` больше нигде не встречаются и остаются в `|0⟩`, что и требуется. Минус 56 из T-count.

**Арифметика.** `ADD(v)` прибавляет константу к регистру данных. Регистр из 10 кубитов, поэтому сложение идёт по модулю `2^10 = 1024`. Пять операций идут подряд на одном и том же регистре, значит, их можно сложить на бумаге:

```
173 + 911 − 337 + 641 − 876 = 512 (mod 1024)
```

`512 = 2^9`, а прибавление `2^9` по модулю `2^10` — это просто переворот старшего бита, в little-endian это кубит `9`. Вся цепочка заменяется на `X(9)`. Минус 665 из T-count и минус 9 кубитов.

**Фазы.** `parity_gadget(mask, c)` — стандартная конструкция «фаза по чётности»: через `CX` в последний кубит маски собирается XOR всех её битов, на него ставится `|c|` штук `T` (или `T†`, если `c < 0`), потом те же `CX` раскручиваются обратно. Биты в итоге не меняются, а состояние получает множитель `ω^c`, если XOR битов маски равен 1. Два гаджета одной маски подряд просто складывают показатели, а `ω^8 = 1`, поэтому коэффициенты внутри маски складываются по модулю 8:

| Маска | Коэффициенты из `_noisy_phase_oracle` | Сумма по модулю 8 |
|---|---|---:|
| `(0, 1, 4)` | `+1, +1, −1` | `+1` |
| `(2, 5)` | `+1` восемь раз | `0` |
| `(3, 6, 9)` | `−1, −1, +1` | `−1` |
| `(1, 7)` | `+1, +1, −1` | `+1` |
| `(0, 8, 9)` | `−1, −1, +1` | `−1` |

Восемь гаджетов на `(2, 5)` в сумме дают `ω^8 = 1` и выкидываются целиком. От остальных остаётся по одному гаджету: `T` на `(0,1,4)`, `T†` на `(3,6,9)`, `T` на `(1,7)`, `T†` на `(0,8,9)`. Итого ровно 4 гейта `T`/`T†` — это и есть потолок бюджета, так что ничего лишнего оставить нельзя. Выкинуть фазы совсем тоже нельзя: биты совпадут с эталоном, но разность фаз перестанет быть константой, и сервер схему отклонит.

Важно соблюсти порядок. Фазовый оракул стоит после слоя `CX`/`X`, поэтому маски читают уже преобразованные биты, и гаджеты должны идти после него. Между собой гаджеты коммутируют, их порядок не важен. Внутри слоя `CX`/`X` порядок менять нельзя: например, `CX(3, 6)` читает кубит `3` уже после `CX(0, 3)`.

Итоговая схема — 26 операций, 12 кубитов, T-count 4, глубина 12:

```
CX(4,5)  X(9)  CX(4,7)  CX(5,8)  CX(0,3)  CX(3,6)  CX(1,8)  X(2)
CX(0,4)  CX(1,4)  T(4)   CX(1,4)  CX(0,4)
CX(3,9)  CX(6,9)  T†(9)  CX(6,9)  CX(3,9)
CX(1,7)  T(7)     CX(1,7)
CX(0,9)  CX(8,9)  T†(9)  CX(8,9)  CX(0,9)
```

В JSON это `"n_qubits": 12` (сервер принимает только 12), `"ancilla_bits": [10, 11]`, у `cx` кубиты идут в порядке (контрольный кубит, целевой кубит). После проверки сервер прогоняет принятую схему через qsim на секретном входе и расшифровывает флаг.
