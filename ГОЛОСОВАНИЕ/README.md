# ГОЛОСОВАНИЕ
**CyberCTF 2026**

Флаг находится в cookie бота-модератора. Значит, задача сводится к XSS в браузере бота, через который можно прочитать `document.cookie` и переслать его к нам.

Идея сервиса - форму с голосованием за продолжение сюжета.

- **`/story-lab`** — «контактная форма». Три параметра из query (`firstname`, `lastname`, `email`) подставляются прямо в атрибуты `value` через фильтр `|safe`, то есть без экранирования:

```startLine:38:40:voting/app/templates/story_lab.html
                        <span>Почта</span>
                        <input id="email" name="email" value="{{ email|safe }}">
```

- **`/report`** принимает относительную ссылку и скармливает её боту. Бот ходит на `web` с cookie `flag`, причём cookie не `HttpOnly` — значит, из JS её видно.
- **`/views/<key>`** — приватный журнал просмотров идеи. Ключ знает только автор идеи, и всё, что пришло в `?viewer=...`, туда записывается и потом показывается. Идеальное место, чтобы «поймать» украденную cookie.

Общая картина складывается сама: отравить `/story-lab`, заставить бота выполнить там наш скрипт, а скрипт пусть отправит cookie в журнал нашей идеи. Остаётся понять, почему «в лоб» это не работает, и обойти три препятствия.


Наивная попытка — просто передать `<script>` или `<img onerror=...>` в параметры — разбивается о защиту:

1. **Фильтр тегов.** Перед рендером `/story-lab` проверяет параметры регуляркой `<[a-zA-Z]`. Любой прямой тег → ответ `500`. Так что ни `<script`, ни `<iframe` в query написать нельзя.
2. **CSP.** Заголовок запрещает инлайн-скрипты: `'unsafe-inline'` есть только для стилей, но не для `script`. Поэтому `onerror=...` и инлайн-обработчики не сработают, даже если протащить их мимо фильтра.
3. **Контекст вставки.** Наши значения попадают всего лишь в атрибут `value` у `<input>`. Сами по себе они ничего не исполняют — нужен кто-то, кто возьмёт это значение и превратит его в живой HTML.

То есть нужно: сломать атрибут **без угловых скобок**, найти функцию, которая сама вставит наш HTML на страницу, и подобрать такой скрипт, который переживёт и фильтр, и CSP.

На странице подключён `subscribe.js` с единственной функцией:

```startLine:1:4:voting/app/static/subscribe.js
function subscribereport() {
  const email = $("#email").val();
  $("#selected_email").html(email);
}
```

Это и есть наш sink: функция берёт значение инпута `#email` и вставляет его через jQuery `.html()` — то есть как настоящий HTML, а не как текст. Два вопроса: как подсунуть сюда свой HTML и кто вызовет `subscribereport()` (в разметке её никто не дёргает).

Оба вопроса решает приём с **DOM clobbering** и гаджетом reCAPTCHA. Ломаем кавычку в `value` и дописываем атрибуты к инпутам.

Через `lastname` превращаем соседний инпут в поддельный виджет reCAPTCHA:

```
x" class="g-recaptcha" data-sitekey="1337" data-error-callback="subscribereport">
```

Подключённый `recaptcha/api.js` находит элемент с классом `g-recaptcha`, пытается отрисовать виджет по ключу `1337`, спотыкается и зовёт колбэк ошибки из `data-error-callback`. А там указано имя нашей функции — `subscribereport`. Так гаджет сам вызывает sink, без валидного site key и без единого инлайн-скрипта.

Через `firstname` вешаем `id=email` на **свой** инпут. jQuery в `$("#email")` берёт первый элемент с таким id в дереве — и это уже не штатное поле почты, а наш инпут, в `value` которого лежит полезная нагрузка. Угловых скобок в параметрах нет, поэтому фильтр молчит: в `lastname` только кавычки и атрибуты, в `firstname` нагрузка спрятана в HTML-сущностях.

Осталось главное препятствие — CSP, которая не даёт выполнить инлайн-код. Хитрость в том, что `.html()` у jQuery вырезает голый `<script>`, но спокойно вставляет `<iframe>`. А документ внутри `srcdoc` iframe — это уже отдельная страница, и там можно подключить скрипт через `src="data:..."`, который CSP как раз разрешает.

Полезная нагрузка (та, что лежит в `value` нашего инпута) записана сущностями, чтобы пройти фильтр, а в DOM браузер раскодирует её обратно в живой HTML:

```
&lt;iframe srcdoc=&quot;
  &lt;script src=&quot;data:text/javascript,fetch('/views/VIEW_KEY?viewer='+encodeURIComponent(document.cookie))&quot;&gt;&lt;/script&gt;
&quot;&gt;&lt;/iframe&gt;
```

Пошагово всё сходится так:

1. Фильтр не видит тегов — в query только сущности.
2. Браузер раскодирует сущности в атрибуте `value`; `$("#email").val()` вернёт уже настоящий HTML.
3. `subscribereport()` кладёт этот HTML через `.html()` — на странице появляется `<iframe srcdoc="...">`.
4. Внутри `srcdoc` грузится `<script src="data:text/javascript,...">`. Схема `data:` разрешена CSP, `'unsafe-inline'` не нужен.
5. Скрипт исполняется в контексте `web`, читает `document.cookie` (а там флаг) и отправляет его в `/views/VIEW_KEY` нашей идеи.

После этого достаточно открыть журнал своей идеи и прочитать флаг.

Коротко по шагам во времени:

```
бот открывает /story-lab?firstname=...&lastname=...
  → браузер строит инпуты с id=email и class=g-recaptcha
  → recaptcha/api.js спотыкается и зовёт subscribereport()
  → .html() вставляет iframe + srcdoc + data:-скрипт
  → fetch /views/VIEW_KEY?viewer=<document.cookie с флагом>
автор идеи открывает /views/VIEW_KEY и видит флаг
```

`solver.py` проходит всю цепочку автоматически:

1. Регистрируется, постит идею и забирает её `view_key` со страницы «Моя идея» — это адрес нашего журнала.
2. Собирает query для `/story-lab`: в `firstname` — нагрузка с iframe/`srcdoc`/`data:`-скриптом и `" id=email>`, в `lastname` — поддельный `.g-recaptcha` с `data-error-callback=subscribereport`. Скрипт внутри делает `fetch('/views/<key>?viewer='+document.cookie)`.
3. Отправляет эту ссылку боту через `POST /report`.
4. Опрашивает `GET /views/<key>`, пока в журнале не появится `CyberCTF{...}`.

```bash
python3 solver.py --base http://127.0.0.1:5001
```

Ожидаемый вывод: `[+] FLAG: CyberCTF{...}` (значение берётся из `FLAG` у бота).

Вручную путь тот же: запостить идею, подставить её `view_key` в нагрузку, отправить ссылку в `/report`, подождать и открыть «Кто смотрел». Payload удобно собирать через `urllib.parse.quote` — внутри `srcdoc` легко запутаться в кавычках и сущностях.
